Включение
---------
LLAMA_EXPERIMENTAL_MOE_TRACE=1 при создании отдельного тестового контекста.
Только точная строка "1" включает диагностику; unset, "0" и другие значения
оставляют её выключенной. Переменная читается один раз в конструкторе.
Она НЕ включает MoE cache, не меняет его бюджет и не меняет placement.
Если cache context не создаётся, новых строк диагностики не будет.

Объём вывода
------------
Одна строка coverage при успешном создании cache и две итоговые строки при
его обычном уничтожении. Нет per-token/per-layer-update логов. Это агрегат
за жизнь cache context, не автоматически за один запрос. Ключ cache=%p
различает одновременно существующие контексты; адрес может переиспользоваться
после уничтожения. no_alloc=1 помечает контексты оценки памяти без allocations:
их нельзя суммировать с реальным inference. При crash/SIGKILL итог не гарантирован.
Штатные строки log_stats сохранены в прежнем виде.

Coverage
--------
model_layers: всего слоёв модели.
expert_layers: слои хотя бы с одним распознанным expert tensor.
all_host_expert_layers: слои, все expert tensors которых удовлетворяют
существующему llama_moe_cache_is_host_weight.
host_layers_without_matching_gpu: из этих host-слоёв те, для которых
model.dev_layer не совпадает с доступным GPU/IGPU backend данного cache.
eligible_layers: host-слои с совпавшим GPU/IGPU backend до распределения бюджета.
configured_cache_layers: слои, которым после распределения бюджета создан
slot map. Это покрытие слоёв, а не число резидентных экспертов или hit rate.

Счётчики
--------
cache_update_calls: успешные вызовы copy для slot map данного cache.
unique_expert_hits/misses: существующие stats_small + stats_large; distinct
expert IDs внутри одного layer update, затем сумма по updates. Это не число
выданных токенов и не глобальная cardinality экспертов за весь запуск.
hit_rate_pct равен 0 при отсутствии requests; при calls=0 это отсутствие
наблюдений, не измеренный нулевой hit rate.
expert_upload_bytes_requested: прежний st.bytes для загрузки miss payloads.
id_readback_bytes_requested: сумма размеров выбранных IDs, запрошенных get_async.
slot_map_upload_bytes_requested: сумма размеров slot maps, переданных set_async.
Все bytes являются логическими размерами аргументов API, не физическими
PCIe counters. D2D copy_experts и обычный bypass больших batches сюда не входят;
их существующая статистика не изменена. Никаких дополнительных IDs или весов
диагностика не считывает.

Времена
-------
Четыре ggml_time_us() только при enabled=1 на успешный cache update.
id_readback_and_existing_sync: host interval от вызова get_async до возврата
УЖЕ СУЩЕСТВУЮЩЕГО backend synchronize. Он включает ожидание ранее поставленной
GPU работы; его нельзя объявлять чистой стоимостью пересылки ID через PCIe.
slru_plan: host interval существующего SLRU plan и минимального control flow.
upload_enqueue: host interval существующих upload loops, обновления штатной
статистики и enqueue slot map. Async API может блокироваться на staging или
page faults. Этот интервал не является временем завершения GPU/DMA.
В итоговой строке явно указаны scope=cache_lifetime и gpu_durations=not_measured.
Эти три интервала не охватывают всё время inference и не являются токен/с.

Неизменность пути
----------------
Не добавлены synchronize, events, CUDA streams или backend operations.
Все прежние backend API calls остались в прежнем порядке.
SLRU policy, routing, экспертные bytes, dispatch, graph, logits и публичные
headers/API/ABI не меняются. Новое состояние находится только в private impl.
При выключенной диагностике нет новых clock calls, счётчиков hot path или
experimental log output. Дополнительные условные проверки и размер impl есть;
нулевой overhead не заявляется ни для disabled, ни для enabled режима.
