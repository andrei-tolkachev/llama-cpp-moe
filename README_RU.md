# llama-cpp-moe

Накопительные 29 патчей к существующей llama.cpp для больших MoE-моделей. Самостоятельный проект с адаптациями Maya и Strata, без изменения форматов GGML и без заявления об официальной поддержке со стороны этих проектов.

На RTX 5090, i9-13900K и 128 ГиБ RAM финальная проверка установленной сборки дала в среднем **78,20 ток/с у Qwen** и **21,23 у DeepSeek после прогрева короткого запроса**. У DeepSeek разброс в этой проверке — 17,51–23,59; прежние сохранённые быстрые запуски давали среднее около 23,7. Постоянные 25 у DeepSeek и 100 у Qwen не подтверждены.

Новый режим отдаёт больше VRAM вычислениям при чтении большого входа, затем возвращает полный кэш экспертов для генерации. KV-контекст остаётся на месте. На реальном некэшированном входе Qwen: **32K — 32,06 с (1022 ток/с), 64K — 61,09 с (1073 ток/с)**. Прежняя настройка на тех же 32K входных токенов занимала 418,56 с (78,29 ток/с). Это отдельные запуски, не ABBA; длинные ответы различались. Выход сразу после 32K/64K составил 48,38/54,52 ток/с, поэтому переносить на него скорость короткого прогретого запроса нельзя.

DeepSeek на фактическом входе 32K/64K показал **46,03/50,78 ток/с на входе** (711,92/1290,61 с) и **10,47/10,54 ток/с на выходе сразу после него**. Это отдельный режим нагрузки; скорость коротких прогретых запросов к нему не относится.

F16 KV, без MTP/DSpark; общий уровень качества не доказан 12 короткими задачами и поиском трёх ключей. Рабочие службы, веса, личные запросы и ключи доступа в пакет не включены. Старые внутренние обозначения оставлены только для связи с историей проверок; публичное имя — llama-cpp-moe.
